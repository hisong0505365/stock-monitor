# DART 감사보고서 PDF 분석 — 기업평가 프로그램용 파싱 설계

분석일: 2026-09-26 · 대상: DART 전자공시 감사보고서 PDF 4건 · 프로토타입: `disclosure_parser.py`

## 1. 결론 요약

1. **OCR이 필요 없습니다.** 4건 모두 DART가 iText 5.4로 생성한 PDF이며 텍스트 레이어(한글 폰트 Gulim/Batang 임베드)와 표 테두리 선이 있습니다. PyMuPDF `find_tables()`로 재무제표의 행과 열이 그대로 복원됩니다.
2. **OCR이 필요한 곳은 한 페이지뿐입니다.** 지오영과 백제약품의 「대표이사 및 내부회계관리자의 운영실태보고서」가 서명 스캔 이미지(JPEG)로 들어 있습니다. 평가에 필요하면 이 페이지만 OCR하면 됩니다.
3. **어려운 부분은 문자 인식이 아니라 양식 차이입니다.** 열 구조, 계정명, 부호 표기, 회계기준, 회계기간이 회사마다 다릅니다. 이를 흡수하는 정규화 계층과 회계 항등식 검증 계층이 핵심입니다.
4. 프로토타입 파서로 4건의 본문 재무제표를 추출해 **항등식 검증 59개 항목을 모두 통과**했습니다(자산=부채+자본, 기말현금 BS↔CF 일치 등).

|---|---|---|---|---|---|---|
| 2026.04.01 | 주식회사 지오영 | 삼정회계법인 | 제24기 2025.01.01~12.31 | K-IFRS | 82 | 적정 |
| 2026.04.02 (A) | 알보젠코리아 주식회사 | 삼정회계법인 | 제70기 2025.01.01~12.31 | K-IFRS | 98 | 적정 |
| 2026.04.02 (B) | 백제약품주식회사 | 대주회계법인 | 제53기 2025.01.01~12.31 | **일반기업회계기준** | 56 | 적정 |

## 3. PDF 기술 특성

| 항목 | 내용 | 파싱 영향 |
|---|---|---|
| 생성기 | iText® 5.4.0 (DART 변환기), PDF 1.4, A4(595×842pt) | 모든 DART 공시 PDF가 같은 변환기를 쓰므로 양식 골격이 일정 |
| 텍스트 | 전 페이지 텍스트 레이어 있음(문서당 4.3만~8만 자) | OCR 불필요, 오인식 없음 |
| 폰트 | Gulim, Batang(서브셋 임베드), Helvetica | 한글 추출 정상 |
| 표 | 셀 테두리가 벡터 선으로 그려짐 | `find_tables()`로 행/열 복원 가능 |
| 이미지 | 지오영 p.80, 백제약품 p.54 각 1장(운영실태보고서 서명 스캔) | 이 페이지만 OCR 대상 |
| 쪽 번호 | 매 페이지 하단 `전자공시시스템 dart.fss.or.kr / Page N` | 본문에서 제거해야 함 |

## 4. 문서 구조

모든 감사보고서가 같은 순서입니다. 페이지 첫 줄(제목)로 구간을 나눌 수 있습니다.

```
p.1   목차
p.2   표지: 회사명, "재무제표에 대한 감사보고서", 감사인, 제N기 회계기간
p.3~5 독립된 감사인의 감사보고서: 감사의견, 감사의견근거, (기타사항), 책임 단락, 감사보고서일
p.6   (첨부)재무제표 표지: 당기·전기 회계기간, 대표이사, 본점 소재지
p.7~  재무상태표 → (포괄)손익계산서 → 자본변동표 → 현금흐름표
      주석 (가장 많은 분량, 40~85쪽)
      [내부회계관리제도 검토의견 + 운영실태보고서 스캔]  ← 지오영, 백제약품만
      외부감사 실시내용: 감사 인원·시간, 주요 감사 일정, 감사위원회 커뮤니케이션
```

## 5. 회사별 양식 차이 (파싱에서 실제로 부딪힌 것)

### 5.1 재무제표 표의 열 구조

| 회사 | 재무상태표 열 | 구조 |
|---|---|---|
| 지오영 | 4열 | `과목 · 주석 · 당기 · 전기` (기간당 1열) |
| 알보젠코리아 | 6열 | `과목 · 주석 · 당기(세부, 합계) · 전기(세부, 합계)` |
| 아주약품 | 8열 | `과목 · 주석 · 당기(2) · 전기말(2) · 전기초(2)`, 기간이 3개 |
| 백제약품 | 5열 | `과목 · 당기(2) · 전기(2)`, **주석 열 없음**(계정명에 `(주석17)` 포함) |

기간 하나가 (세부, 합계) 2열로 나뉜 경우 헤더 두 번째 칸이 비어(None) 있으므로, 빈 헤더는 앞 기간을 이어받게 처리했습니다. 알보젠 포괄손익계산서의 `확정급여제도의 재측정요소`처럼 **같은 표 안에서도 당기는 세부 열, 전기는 합계 열에 값이 들어간 행**이 있어, 열 위치로 소계 여부를 판단하면 안 되고 기간별로 값이 있는 열을 채택해야 합니다.

### 5.2 계정명과 계층

- 계층 접두어가 네 종류 섞여 있습니다: `Ⅰ.`(유니코드 로마숫자), `I.`/`VII.`/`X.`(라틴 문자), `(1)`, `1.`, `가.`~`러.`. 백제약품에는 `ⅩⅠ.`처럼 두 글자 로마숫자도 있습니다.
- 공백이 들어간 합계 행: `자 산 총 계`, `부 채 및 자 본 총 계`.
- 셀 안 줄바꿈: `당기손익-공정가치측정금융\n자산`.
- 같은 개념의 다른 이름: `매출채권` / `매출채권및기타채권`, `단기차입금` / `차입부채`, `유동성장기차입금` / `유동성장기부채`, `금융비용` / `금융원가`, `법인세비용차감전순이익` / `법인세차감전이익`.
- 일반기업회계기준(백제약품)은 `(1) 당좌자산`, `대손충당금`·`평가충당금` 차감 행, `영업외수익/비용`, 매출원가 구성(기초재고+매입−기말재고) 등 계정 체계 자체가 다릅니다.

→ 접두어와 공백을 제거한 뒤 **표준 계정 동의어 사전**으로 매핑해야 합니다(`STANDARD_ACCOUNTS`).

### 5.3 부호 표기

| 항목 | 지오영 | 알보젠·아주약품·백제약품 |
|---|---|---|
| 매출원가, 판관비 | `(3,309,341,062,502)` 괄호(음수) | 양수 |
| 법인세비용 | 괄호 = 비용 | 양수 = 비용, 괄호 = **수익**(아주약품 전기 `(57,409,108)`) |
| 현금흐름표 유형자산의 취득 | 괄호 | 아주약품은 같은 유출 소계 아래에서 **양수** |

비용 항목은 절대값으로 통일하고, 법인세는 "매출원가가 음수로 표기된 문서인가"로 문서의 부호 관례를 판별해 뒤집습니다. 부호 오류는 항상 항등식 검증(§7)으로 확인합니다.

### 5.4 원문 자체의 표기 오류

알보젠 현금흐름표의 `현금및현금성자산의 감소` 행 값은 `13,534,470,143`(양수)이고 기초 245.9억 → 기말 381.4억으로 실제로는 **증가**입니다. 라벨을 믿지 말고 `기초 + 증감 + 환율효과 = 기말`로 검증해야 합니다.

### 5.5 회계기간

아주약품은 물적분할로 신설된 법인(제2기)이고 **전기가 2025.03.04~03.31, 28일**입니다. 전기 매출 180억과 당기 2,465억을 그대로 비교하면 성장률이 1,268%로 나옵니다. 또 전기 재무제표는 감사받지 않았다고 헤더에 표기돼 있습니다(`(감사받지 않은 재무제표)`). 결산월도 3월입니다.

→ (첨부)재무제표 표지에서 당기·전기 기간을 모두 읽어 일수를 계산하고, 전기가 당기의 90% 미만이면 성장률을 계산하지 않고 경고를 붙입니다.

### 5.6 페이지 넘김

백제약품의 재무상태표·손익계산서·현금흐름표는 각각 2쪽에 걸쳐 있고, 두 번째 쪽 표에는 헤더가 없습니다(첫 행이 `Ⅰ. 유동부채`). 지오영 재무상태표도 자본 항목 5행이 다음 쪽으로 넘어갑니다. → 제목 없는 페이지의 표는 직전 재무제표의 연속으로 보고 직전 열 구조를 재사용합니다.

### 5.7 텍스트 순서와 표 위치

`page.get_text()`의 기본 출력은 본문 텍스트를 먼저, 표를 페이지 끝에 몰아서 내보냅니다. 주석에서 "(1) 단기차입금의 내역은 다음과 같습니다" 문장과 해당 표가 떨어져 나오므로, **텍스트 블록과 표를 y좌표로 정렬**해야 캡션·단위·표·각주(`(*1)`)를 연결할 수 있습니다.

### 5.8 단위

본문 재무제표는 4건 모두 `(단위: 원)`이지만 주석 표는 `(단위: 천원)`인 회사가 많습니다(지오영, 알보젠, 백제약품). 표기도 `(단위: 원)`, `(단위 : 원)`, `(단위:원)`이 섞여 있어 표마다 바로 위 단위 문자열을 붙여서 저장해야 합니다. 지오영 단기차입금 주석 합계 `122,425,000`천원 = 재무상태표 `122,425,000,000`원처럼 단위 환산 후 본문과 대사하면 검증 수단이 됩니다.

### 5.9 주석 번호

같은 주석이라도 번호가 다릅니다(차입금: 아주약품 16, 알보젠 16 "차입부채", 백제약품 7, 지오영 20). 주석은 번호가 아니라 **제목 키워드**로 찾아야 합니다. 병합 셀(차입처가 여러 행에 걸침)은 `None`으로 나오므로 앞 행 값으로 채워야 합니다.

## 6. 감사보고서에서 뽑을 수 있는 정성 정보

| 항목 | 위치/판정 방법 | 4건 결과 |
|---|---|---|
| 감사의견 | "…공정하게 표시하고 있습니다" / "있지 않습니다" / "의견을 표명하지 않습니다" / "한정의견" | 모두 적정 |
| 계속기업 불확실성 | "계속기업으로서의 존속능력에 유의적 의문" | 없음 |
| 핵심감사사항(KAM) | 비상장 외감법인은 대상이 아님 | 없음 |
| 기타사항 | 전기 감사인 변경, 미감사 전기 재무제표 등 | 아주약품(전기 미감사), 백제약품(전기 타감사인) |
| 회계기준 | 감사의견 문단의 "…에 따라, 중요성의 관점에서" | 백제약품만 일반기업회계기준 |
| 감사보고서일 | `감사보고서일(날짜)`, "귀중" 뒤, 서명란 앞 등 위치가 제각각 | 추출 완료 |
| 내부회계관리제도 | 검토의견 섹션 유무 | 지오영, 백제약품 |
| 감사시간 | 외부감사 실시내용 표 | 지오영 1,831h → 1,115h(−39%) |

본문 전체에서 키워드를 찾으면 오판합니다. 예를 들어 백제약품 주석에 "한국채택국제회계기준"이라는 문구가 있어 전체 검색으로는 K-IFRS로 잘못 판정됐습니다. 판정은 감사보고서 본문(표지~첨부 표지 사이)으로 범위를 제한해야 합니다. 또 한글이 줄 중간에서 끊기므로(`재\n무제표`) 공백·줄바꿈을 제거한 문자열로 검색합니다.

비교하다 발견해 구간(유동/비유동) 구분 매핑으로 고쳤다 — `docs/parsing_accuracy.md` 참고.

평가 로직 설계 시 참고할 점:

- 지오영·백제약품(의약품 도매)과 알보젠·아주약품(제약)은 수익 구조가 다릅니다. 도매업은 매출총이익률 5~6%에 매입채무가 부채의 대부분이라 부채비율이 290~495%로 높지만, 차입금의존도는 5~17%로 낮습니다. **부채비율 단독 평가는 도매업을 과소평가하므로 업종별 기준과 차입금 기반 지표를 함께 써야 합니다.**
- 두 도매업체는 전기 영업활동현금흐름이 음수였다가(지오영 −337억, 백제약품 −7억) 당기 양수로 돌아섰습니다. 한 해 수치보다 다년 추세가 필요합니다.
- 이자비용은 K-IFRS 3건에서 손익계산서에 따로 없고 금융비용/금융원가에 섞여 있습니다. 프로토타입은 현금흐름표 `이자의 지급`으로 대체했습니다. 정확히 하려면 금융비용 주석 표를 파싱해야 합니다.

## 9. 사업보고서·반기·분기보고서로 확장할 때 (샘플 확인 필요)

이번 샘플은 감사보고서만 있어 아래는 DART 양식 기준의 예상이며, 실제 샘플로 확인해야 합니다.

- **사업보고서**: 재무 외 섹션(사업의 내용, 주주, 임원 등)이 앞에 있고 재무제표는 「III. 재무에 관한 사항」 안에 있습니다. 연결재무제표와 별도재무제표가 모두 있고, 요약재무정보는 3개년입니다. `연결` 접두어를 구분해야 하며(`STATEMENT_TITLES`에 반영) 감사보고서는 첨부서류로 따로 붙습니다.
- **반기·분기보고서**: 감사가 아니라 **검토보고서**이므로 의견 문구가 다릅니다("…중요성의 관점에서 공정하게 표시하지 않은 사항이 발견되지 아니하였습니다"). 손익계산서에 `3개월`과 `누적` 열이 기간마다 따로 있어 열 구조가 더 복잡합니다. 재무상태표의 비교 시점은 전기말입니다.
- 어떤 보고서든 재무 수치는 **연환산 여부와 기간 일수**를 함께 저장해야 합니다(분기 이익을 연간 지표와 섞지 않도록).

## 10. 권장 아키텍처

```
[수집]  OpenDART API ──(상장사·사업보고서 제출대상)──▶ XBRL 재무제표 API: 파싱 불필요
           │
           └─(감사보고서만 내는 비상장 외감법인)──▶ 공시서류 원본(XML) 또는 PDF
                                                          │
[파싱]  1) 텍스트 레이어 확인 ─ 있음 → PyMuPDF 표 추출 (이번 4건 전부)
                          └ 없음 → OCR (서명 스캔 페이지 등 예외)
        2) 구간 분리: 표지 / 감사의견 / 재무제표 4종 / 주석 / 외부감사 실시내용
        3) 표 정규화: 헤더→기간 매핑, (세부·합계)열 병합, 페이지 넘김 연결, 병합셀 채움
        4) 계정 정규화: 접두어·공백 제거 → 표준 계정 사전 매핑, 부호 통일, 단위 환산
[검증]  5) 회계 항등식 + 본문↔주석 대사 → 실패 시 수동 검토 큐
[평가]  6) 재무비율(기간 일수 반영) + 감사 정성지표 → 업종별 기준으로 점수화
```

- 비상장 외감법인 감사보고서는 XBRL 재무제표 API로 받을 수 없는 경우가 많아 문서 파싱이 필요합니다. 다만 DART 원본은 XML(표가 `TABLE/TR/TD` 태그로 구조화)이므로, OpenDART의 공시서류 원본파일 API로 XML을 받을 수 있으면 PDF보다 안정적입니다. PDF 파서는 사용자가 직접 올린 파일이나 API로 받을 수 없는 경우를 위한 경로로 두는 것을 권장합니다. (API 제공 범위와 조건은 OpenDART 문서에서 확인 필요)
- OCR(Tesseract/PaddleOCR 등)은 텍스트 레이어가 없는 페이지에만 쓰는 예외 경로로 두세요. DART PDF 전체를 OCR하면 숫자 오인식(`8`↔`6`, 쉼표 누락)이 생기고, 텍스트 레이어로 얻는 정확한 값을 버리게 됩니다.

## 11. 기업평가 지표 후보

| 구분 | 지표 | 데이터 출처 |

| 수익성 | 매출총이익률, 영업이익률, ROE, ROA | IS, BS |
| 성장성 | 매출·영업이익 성장률(기간 일수 보정) | IS, 첨부 표지 기간 |
| 활동성 | 매출채권·재고·매입채무 회전일수, 현금전환주기 | BS, IS |
| 현금흐름 | 영업CF, FCF(영업CF − CAPEX), 영업CF/순이익 | CF |
| 상환능력 | 이자보상배율, 단기차입 비중, 연도별 상환계획 | IS, CF, 차입금 주석 |
| 감사 품질 | 감사의견, 계속기업 불확실성, 감사인 변경, 감사시간 증감 | 감사보고서 본문, 외부감사 실시내용 |
| 우발 위험 | 지급보증, 담보제공, 소송, 특수관계자 거래 규모 | 주석(제목 키워드 검색) |

## 12. 프로토타입 사용법

```bash
pip install pymupdf
python disclosure_parser.py 감사보고서.pdf
```

출력(JSON): `meta`(회사, 감사인, 기간, 회계기준, 감사의견, 감사시간, 텍스트 없는 페이지), `statements`(재무제표별 페이지·기간·행 수), `standard`(표준 계정 값), `validation`(항등식 결과), `ratios`, `warnings`.

현재 범위와 한계:

- 본문 재무제표 4종과 감사보고서 메타데이터만 다룹니다. 주석 표(차입금, 특수관계자, 우발부채 등)는 아직 구조화하지 않았습니다.
- 표준 계정 사전은 이번 4건에 맞춘 최소 버전입니다. 새 문서마다 매핑 실패 계정을 모아 사전을 늘려야 합니다.
- 연결재무제표, 검토보고서(분·반기), 사업보고서는 샘플로 검증하지 않았습니다.
- 샘플 PDF는 저장소에 포함하지 않았습니다.

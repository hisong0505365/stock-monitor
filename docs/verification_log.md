# 검증 → 개선 기록

검증에서 틀린 것을 찾으면 **고치고, 같은 실수를 다시 잡는 테스트를 남긴다.** 이 파일은 그 기록이다.
새 감사보고서·새 거래처 양식에서 문제가 나오면 여기에 한 줄 추가하고 회귀 테스트를 만든다.

## 2026-09-27 · 3차 — 새 감사보고서 5건 파싱 · OCR 정확도

대상: 티제이팜 · 복산나이스 · 인천약품 · 동원약품 · 경동사(모두 일반기업회계기준, 감사인 5곳, 경동사는 완전자본잠식).
방법·수치 전체는 `docs/parsing_accuracy.md`.

### 시험했지만 버린 것

- **계정명 사전 보정**: 다른 보고서 계정명 중 가장 가까운 이름으로 바꾸면 정확 일치가 오히려 떨어지고, 깨진 이름에만 써도 26~35% 가 그럴듯한 다른 계정(`장기대여금의감소` → `단기대여금의감소`)이 됨. 조용한 오답이라 채택 안 함.
- 숫자 열 전체를 숫자 전용으로 한 번에 OCR: 기준선보다 나쁨(1,568 / 1,750).

### 결과

- 파서: 정답표 240 / 240, 구조 2,681 / 2,681, 항등식 129 / 129
- 평가: 티제이팜 BBB(64.7) · 복산나이스 AA(81.7) · 인천약품 A(77.7) · 동원약품 AAA(91.6) · 경동사 C(18.8, 완전자본잠식)
- OCR 숫자 2,554 → 2,681 / 2,681 (스캔 조건 포함), 계정명 9.3% → 84.8%

### 아직 검증 못 한 것

- 실제 종이 스캔 PDF — 이번 OCR 수치는 깨끗하게 렌더링한 이미지 기준
- 조각 병합·대시 규칙(#7 일부)은 1차 문서를 보고 만들어 따로 검증한 문서가 없음
- 연결재무제표·반기·분기 보고서

## 2026-09-26 · 2차 — 대시보드 연동 코드(credit_export) 실제 적재 검증

### 정상으로 확인된 것

- 마이그레이션 제약조건(NOT NULL·FK·CHECK·PK) 아래에서 3개 테이블 적재, 다시 돌려도 행 수 불변(멱등)
- 보호 규칙: dart-analyzer 평가(다른 원본) 유지, 수동 매칭 유지, no_match → matched 갱신, 기존 회사 이름 유지
- 합성 거래처 9,500곳에서 오매칭 0건, 1,000행 넘는 조회의 커서 페이지 처리
- 승인 사용자는 읽히고, 비로그인은 0행(RLS)
- 대시보드가 DB 에서 읽은 실제 행을 오류 없이 그림(데스크톱·가로 넘침 없음)

### 아직 검증 못 한 것

- 실제 Supabase(PostgREST HTTP)와 OpenDART 호출 — 네트워크 정책으로 차단. HTTP 계층은 가짜 세션 단위 테스트뿐
- 새 감사보고서(연결·반기·분기·다른 감사인) — DART 차단으로 수집 불가
- 스코어카드 기준값·업종 보정 폭 — 부도·연체 이력 없이는 검증 불가(업종 보정만으로 지오영 +17점)

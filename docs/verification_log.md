# 검증 → 개선 기록

검증에서 틀린 것을 찾으면 **고치고, 같은 실수를 다시 잡는 테스트를 남긴다.** 이 파일은 그 기록이다.
새 감사보고서·새 거래처 양식에서 문제가 나오면 여기에 한 줄 추가하고 회귀 테스트를 만든다.

## 2026-09-26 · 2차 — 대시보드 연동 코드(credit_export) 실제 적재 검증

### 검증 방법

| 검증 | 방법 |
|---|---|
| DB 적재 | 로컬 PostgreSQL 16 에 ar-dashboard 마이그레이션 0001~0031(0025 pg_net 제외)을 그대로 적용하고, PostgREST 가 upsert 를 실행하는 SQL(`json_populate_recordset` + `ON CONFLICT`)을 흉내 내 `--upload` 끝까지 실행 (`tests/pg_rest.py`) |
| 거래처 매칭 | 1100 조직 실제 분포(의원 4,489 · 약국 2,593 · 그외 1,026 · 도매 903 · 병원 378)를 본뜬 합성 거래처 9,500곳 + 붙어야 할 이름 7개 + 붙으면 안 되는 미끼 8개 |
| 기존 데이터 보호 | dart-analyzer 평가·수동 매칭·no_match 매칭을 미리 넣어 두고 적재 |
| 대시보드 읽기 | 승인 사용자 / 비로그인 권한(RLS)으로 조회 → 기업신용평가 화면에 실제 적재 행을 그려 확인 |
| 감사의견 판정 | 실제 감사보고서 본문(지오영)을 한정·부적정·의견거절·계속기업 불확실성으로 바꾼 변형 7종 |
| 폴더 운영 | 같은 보고서 사본(`… (1).pdf`)과 감사보고서가 아닌 PDF 가 섞인 폴더 |

DART·OpenDART 는 이 작업 환경의 네트워크 정책으로 막혀 있어(403) 새 보고서 수집과 OpenDART

### 정상으로 확인된 것

- 마이그레이션 제약조건(NOT NULL·FK·CHECK·PK) 아래에서 3개 테이블 적재, 다시 돌려도 행 수 불변(멱등)
- 보호 규칙: dart-analyzer 평가(다른 원본) 유지, 수동 매칭 유지, no_match → matched 갱신, 기존 회사 이름 유지
- 합성 거래처 9,500곳에서 오매칭 0건, 1,000행 넘는 조회의 커서 페이지 처리
- 승인 사용자는 읽히고, 비로그인은 0행(RLS)
- 대시보드가 DB 에서 읽은 실제 행을 오류 없이 그림(데스크톱·가로 넘침 없음)

### 아직 검증 못 한 것

- 실제 Supabase(PostgREST HTTP)와 OpenDART 호출 — 네트워크 정책으로 차단. HTTP 계층은 가짜 세션 단위 테스트뿐
- 새 감사보고서(연결·반기·분기·다른 감사인) — DART 차단으로 수집 불가
- 스코어카드 기준값·업종 보정 폭 — 부도·연체 이력 없이는 검증 불가(업종 보정만으로 지오영 +17점)
